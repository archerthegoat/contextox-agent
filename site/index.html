01 / 问题

困难往往不在计算，而在定义。

同一个业务目标，资料里可能只有字段名；真正决定结果的口径，留在说明文档、会议和人的经验里。

“按地区统计订单金额。”

一句看似清楚的需求，至少还缺三项会改变结果的决定。

  1. Q-01退款金额是扣除、单列，还是仍算入订单额？
  2. Q-02订单金额缺失时，是排除、归零，还是标记异常？
  3. Q-03统计按下单、支付还是退款时间归属？
02 / 方法

Agent 找证据，人确认业务事实。

数契把一次对话组织成四个可回读的阶段，让资料、候选结论、人的回答和未知事项各自保持身份。

01

选择资料

本轮明确使用哪些资料及其精确版本。

02

说出目标

在右侧直接对话，资料和目标足够时开始分析。

03

确认口径

Agent 把会改变结果的问题整理成可修改回答卡片。

04

核对成果

中间查看字段、关系、出处、变化与仍未知事项。

03 / 演示

从一句目标，到可核对的候选定义。

以下流程来自正式 React／Python Workbench 的公开合成实例。它展示产品操作，不代表真实企业结论。

回答确认以后

  • 字段规则订单合计扣除同地区已退款金额
  • 缺失处理不计入净额，并单独列出
  • 候选关系订单与退款按地区关联
  • 仍需确认本次统计采用什么时间范围
