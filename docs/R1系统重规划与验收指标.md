# R1 重规划与验收指标

状态：DRAFT / 待批准。日期：2026-09-07。

本稿只提出开发路径和验收规则，不表示新架构合同、接口、迁移、模型试验或 Git 外部交付已获批准。规划基于 `codex/positioning-alignment@1fff2d9`。研究交付中的精确补丁只修改《开发路径图》和《Agent任务协作开发实施计划》的指定段落，并将本稿新增为 `docs/R1系统重规划与验收指标.md`。当前补丁未应用；正式生效必须以人批准的精确文本和后续应用回执为准。《架构与迁移报告》本次不修改。

## 1. 目标与保留

R1 必须在同一业务定义任务中完成至少两轮用户可见交互，给出准确的资料解释、证据支持的关系、字段定义候选和具体澄清。合法 partial、输入框、工具执行或生成对象不足以单独通过。

保留本地 Python/React/SQLite、薄 Agent Loop、已有来源解析与 Workbench 基础、Workspace/来源授权、不可变版本、CAS/hash、受控批准及完成语义。三类已批准用户共用证据与业务定义流程，FDE 仍为首个实际试点。不因本次重规划新增角色系统、课程、连接器、框架或 Provider。

## 2. 开发检查点

| 检查点 | 具体任务与交付 | 通过条件 |
| --- | --- | --- |
| G0 合同及评测冻结 | 对齐模型可执行工具合同、领域不变量、证据覆盖、可恢复错误、联合预算与观测；准备公开/合成参考案例；同步评审 R1/R2 接缝 | 精确合同与参考答案经评审；关键反例有处理；重大接口、数据与成本决定获人批准 |
| G1 成套工程实现 | 提供真实有界证据目录/工作集；减少模型拼装持久身份；实现保持语义的候选校验与有界恢复；补足安全诊断；Workbench 显示真实产物和失败状态 | 公开接缝及必要故障测试通过；生成合同无漂移；构建、隔离运行和范围检查通过；真实语义验收仍 PENDING |
| G2 R1 真实质量 | 固定版本和预算执行完整两轮任务；检查事实、引用、关系/字段、未知及澄清；记录重复案例和资源 | 第 3-4 节指标通过；无法执行的部分保持 NOT RUN/PENDING；人工验收独立记录 |
| G3 R2 回答闭环 | 整份回答批准；unknown 卡点与解决方；原请求新版本重批；新 Run 消费精确批准快照并呈现草案差异 | 真实任务与浏览器回读核对；旧 Run 保持旧回答；未知不伪装解决；精确构建人工验收 |

G0 可同步开展 R2 合同对齐。G1 通过后，若 R2 精确接口和迁移已经独立获批，可推进局部 Store/API/Workbench；无需等待所有 G2 试验结束。这是依赖上的并行，不强制多个 Agent。G3 完整真实验收必须等待 G2，工程并行不能改变路径 2 通过门。

正式 Contract、Mission 完成和第二任务批准知识复用继续遵循路径 3、4，不与本批 R0-R2 局部闭环混同。路径 5 的公平收益比较仍在完整闭环后开展，路径 2 起收集基础数据；不把基线评测设为 R1 开工条件。

## 3. 必须冻结的验收定义

评测单位：一个从独立、已授权起点开始的完整案例，至少两轮用户可见交互。参考事实、关键未知、必需候选与评分规则在查看模型答案前冻结；接受语义等价的正确答案，不限定字段命名与工具轨迹。

| 指标 | 分母与建议阈值 | 责任方 |
| --- | --- | --- |
| 安全及裁决边界 | 全部已执行试验；严重违规 0 次，任一次即停止该批 | 开发负责程序验证，产品负责人核验裁决语义 |
| 事实覆盖 | 预先标注的必需事实；关键 100%，其他 ≥90% | 案例/业务评审者 |
| 引用支持 | 所有需来源支撑的事实主张；关键 100%，整体 ≥95%；定位有效也须内容支持 | 案例/业务评审者 |
| 未知与冲突 | 预标注关键未决项召回 100%；关键已知误报未知 0 | 业务及数据负责人按职责核对 |
| 候选产物 | 参考要求的关系、字段及未知均持久可回读，无关键语义错误 | 开发核对状态，业务评审语义 |
| 可执行澄清 | 每个关键卡点有问题、影响、对应角色、所需证据和下一动作 | 产品与对应解决方 |
| 连续性 | 消息、产物、来源及回答版本正确；刷新不丢失、不重复发起；跨 Workspace 隔离 | 开发自动验证与人的实际浏览器验收分别记录 |
| 资源 | 全部请求计入，已知/未知分开；不超过获准联合上限；报告总量、p50/p90 和失败阶段 | 开发与账户/预算负责人 |

严重违规包括越权、伪造批准或 Mission 完成、静默丢失版本、未知用量补零、擅自把未定业务口径写成已定事实。业务未知导致的合法 partial 不算程序故障，但若未交付本案例应有的候选或澄清，则该完整案例仍未通过。

语义评分由人复核关键项；自动规则/模型辅助评分不得记录人的 PASS。只有一名评审者时明确局限。上述数字是待批准项目阈值，不是行业事实或生产 SLA。

## 4. 样本与试验卡

- 四类开发案例：原始案例、已知充分但有干扰、多来源冲突、读取边界/材料缺失。
- 八个不用于调优的公开/合成保留案例，在字段、材料、未知与约束上变化。
- 建议正式批共 27 个完整案例试验：原始案例 3 次须 3/3；保留集 8×3 至少 22/24，且每个案例至少 2/3；全部已执行试验严重违规为 0。
- 原始三次先作为哨兵，未达标不继续正式批。失败和停止记录保留；未执行记 NOT RUN。用来调优的保留案例退出保留集，补充未见案例并重新冻结版本。
- 按一次草案请求加两个各至多 8 次模型请求的流程，27 案例至多 459 次请求。此为规划上界示例，不是调用授权。另行冻结草案、恢复、输入/输出总量、时间和费用封顶；开发校准批单列预算，不计入正式成绩。预算不足时分阶段执行，正式门保持 PENDING，不拼接不同配置的最佳结果。
- 记录代码/前端构建、模型与参数、prompt、工具合同、材料及 rubric 指纹。所有试验独立起点，未批准内容不得从先前试验渗入。

## 5. 失败与未知结果

权限/来源错误拒绝；已知无副作用的格式/定位错误允许有界、计费计时的反馈恢复；CAS 冲突与已发生写入必须显式回读，不当作整批未执行；Provider 未知请求不自动重发、不补零、不抹去回执。

同一 Mission 的现行未知结果阻塞规则保留。新的独立研发实验必须有单独身份、明确授权及总预算，不复用未知结果、不重放未知业务副作用、不改旧回执，也不据此解锁旧 Mission。若要改变旧 Mission 解锁合同，另行评审。

安全观测只收集白名单错误码/字段路径、阶段时间、组件体积、已观察到的 Provider ID、用量及版本指纹；不保存原始 Provider payload、隐藏推理、秘密或敏感值。上下文优化须遵守已选 Provider 的工具会话协议。

## 6. R2 已定约束

整份回答一起批准；允许批准“尚不能确认”的记录并继续，但问题保持未解决。每个此类卡点列明解决方、所需证据、下一动作。新增事实应更新原澄清请求的整份新版本并重新批准；旧 Run 保留旧回答快照。批准未知记录不是批准业务结论，也不是 Mission 完成。

精确 API、字段、重开/替代规则、版本绑定、恢复与迁移仍须展示合同后评审，本稿不代替该决定。

## 7. 审查与生效

已核对目标、权限、版本、预算、语义评分和反例。通过工程门不提升真实模型、人验或价值状态；模型写出完整答案不证明学习收益；单案例成功不证明稳定；格式恢复不允许业务猜测或重放未知副作用。

批准本稿及其精确补丁后，仅应用已展示的规划文字。下一步为 G0 精确合同和有限试验卡。开发实现、模型调用及 Git 整合沿各自授权执行；本次规划批准不自动授权尚未展示的接口、迁移、真实试验或 push/merge。
