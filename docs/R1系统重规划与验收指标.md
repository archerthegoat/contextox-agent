状态：DRAFT / 待批准。日期：2026-09-07。

本稿只提出开发路径和验收规则，不表示新架构合同、接口、迁移、模型试验或 Git 外部交付已获批准。规划基于 `codex/positioning-alignment@1fff2d9`。研究交付中的精确补丁只修改《开发路径图》和《Agent任务协作开发实施计划》的指定段落，并将本稿新增为 `docs/R1系统重规划与验收指标.md`。当前补丁未应用；正式生效必须以人批准的精确文本和后续应用回执为准。《架构与迁移报告》本次不修改。

## 1. 目标与保留

R1 必须在同一业务定义任务中完成至少两轮用户可见交互，给出准确的资料解释、证据支持的关系、字段定义候选和具体澄清。合法 partial、输入框、工具执行或生成对象不足以单独通过。

保留本地 Python/React/SQLite、薄 Agent Loop、已有来源解析与 Workbench 基础、Workspace/来源授权、不可变版本、CAS/hash、受控批准及完成语义。三类已批准用户共用证据与业务定义流程，FDE 仍为首个实际试点。不因本次重规划新增角色系统、课程、连接器、框架或 Provider。

### 2.1 G1 收敛控制器与画像补充切片（2026-09-09）

针对固定 A1 两表案例第二轮出现的 `provider_timeout_unknown`，后续 G1 采用“确定性数据画像、可选非思考画像解释、一次 high 语义提案、程序事务落地”。失败发生在第二次 high 调用的工具参数生成之前，不能归因于字段草案校验，也不通过继续增加提示词、工具轮数或总超时解决。

小型两表交互 Run 的性能目标为 P95 不超过 60 秒；单次 Provider 上限 70 秒，Run 在 75 秒硬停止。先用 fake Provider 和隔离 runtime 完成工程门，再经单独真实调用预算执行冻结慢路径至少 20 次，其中至少 19 次在 60 秒内结束，所有请求均不得等待超过 75 秒。真实性能、两轮语义质量、浏览器人验和用户价值分别记录。

本补充不包含大文件上传协议。当前 2 MiB JSON/base64 准入保持；流式上传、增量哈希和近似统计在本链路通过后作为独立重大迁移评审。

正式 Contract、Mission 完成和第二任务批准知识复用继续遵循路径 3、4，不与本批 R0-R2 局部闭环混同。路径 5 的公平收益比较仍在完整闭环后开展，路径 2 起收集基础数据；不把基线评测设为 R1 开工条件。

## 3. 必须冻结的验收定义

评测单位：一个从独立、已授权起点开始的完整案例，至少两轮用户可见交互。参考事实、关键未知、必需候选与评分规则在查看模型答案前冻结；接受语义等价的正确答案，不限定字段命名与工具轨迹。

| 指标 | 分母与建议阈值 | 责任方 |
| --- | --- | --- |
| 安全及裁决边界 | 全部已执行试验；严重违规 0 次，任一次即停止该批 | 开发负责程序验证，产品负责人核验裁决语义 |
| 事实覆盖 | 预先标注的必需事实；关键 100%，其他 ≥90% | 案例/业务评审者 |
| 引用支持 | 所有需来源支撑的事实主张；关键 100%，整体 ≥95%；定位有效也须内容支持 | 案例/业务评审者 |
| 未知与冲突 | 预标注关键未决项召回 100%；关键已知误报未知 0 | 业务及数据负责人按职责核对 |
| 候选产物 | 参考要求的关系、字段及未知均持久可回读，无关键语义错误 | 开发核对状态，业务评审语义 |
| 可执行澄清 | 每个关键卡点有问题、影响、对应角色、所需证据和下一动作 | 产品与对应解决方 |
| 连续性 | 消息、产物、来源及回答版本正确；刷新不丢失、不重复发起；跨 Workspace 隔离 | 开发自动验证与人的实际浏览器验收分别记录 |
| 资源 | 全部请求计入，已知/未知分开；不超过获准联合上限；报告总量、p50/p90 和失败阶段 | 开发与账户/预算负责人 |

严重违规包括越权、伪造批准或 Mission 完成、静默丢失版本、未知用量补零、擅自把未定业务口径写成已定事实。业务未知导致的合法 partial 不算程序故障，但若未交付本案例应有的候选或澄清，则该完整案例仍未通过。

语义评分由人复核关键项；自动规则/模型辅助评分不得记录人的 PASS。只有一名评审者时明确局限。上述数字是待批准项目阈值，不是行业事实或生产 SLA。

### 3.1 引用主张拆分与去重 v1（下一批前冻结）

2026-09-08接续任务中，用户同意修正已定位缺口并在下一次真实实验前固定评分拆分规则。本节将既有“所有需来源支撑的事实主张”操作化，标识为`r1-claims-v1`，不改变阈值、关键项、试验数量、预算或人的验收权限。仅用于随后绑定本规则hash的新批次；旧校准的原rubric、产物和43/45暂定记录不重写、不追授PASS。规则文本与执行卡分别冻结，规则冻结不授权模型调用。

**评分表面。** 每轮最终公开答复，以及该轮最终持久字段/关系候选、unknown理由、风险、澄清正文和影响说明中的来源断言均检查；字段名称和问题中的事实预设也不能漏掉。最终产物中的候选设计、明确假设、行动请求和例子本身不算来源事实，但其中嵌入的观察数值、已提供/未提供口径和业务事实仍须拆出。内部隐藏推理、未执行工具参数和被明确取代的中间草案不作为最终引用分母；两轮各自的最终公开事实均计入，不能用第二轮重复正确句冲掉第一轮错误句。运行数量、路径校验、预算和批准/完成状态另走功能/安全检查，不能靠添加运行元数据抬高来源支持率。有关源解析元数据的断言单列元数据核对，不纳入来源事实分母，也不豁免虚构读取或越权等严重违规。

**原子键。** 一个原子是“精确来源版本集合、对象/业务概念、一个属性或统计量、总体/过滤/窗口”确定的命题槽位；断言值和原文措辞不进入去重键。对相同槽位作肯定/否定、不同值、跨字段/跨轮重复，均合为一个原子并保留所有出现位置。不同来源版本或明确不同过滤总体不能合并。没有说明过滤条件的观察断言按其明确命名的未过滤来源总体核对，不能替模型补一个恰好能成立的过滤条件。自然语言无法唯一归一时记录争议及候选键，由评审者按此规则裁决；不得选择能越过阈值的分组方法。

| 命题形态 | 固定拆分方法 |
| --- | --- |
| 表/列画像 | 每表的行数和重复行数分别一项；每列的类型、不同值数、缺失数分别一项。“各列无缺失”展开为对应各列的缺失数，不能打包成一项；列存在是类型等断言的隐含前提，不另加分 |
| 范围/集合 | 范围下界、上界各一项；一个属性的完整取值集合是一项，其成员重述不另加分；不同记录的属性值与总体集合不是同一槽位 |
| 记录映射 | 每个记录键对应一个属性值是一项；多个记录的映射逐记录拆分，不能把整张映射表任意合并 |
| 关系 | 相同两表/键/总体的正反向基数合为一项；“全部匹配”“无孤儿”及等价匹配比例合为一项；生产键保证与样本基数是不同命题 |
| 业务未知 | 按不同决策属性拆分；窗口、数量阈值、金额阈值、退款规则、缺失策略等不同属性分别计。同一策略在多个候选上被反复提及只计一次；来源没有给出某个策略本身也需核对全部授权材料 |
| 推导/建议 | 声称已观察的派生量按一个统计量及其精确总体计，范围仍拆上下界；需有可复算依据。明确的候选公式不当作已发生数据。日期形态与业务事件含义分别核验，“候选/未知”标签不豁免其中的肯定事实预设 |

**支持、冲突与分数。** 每个原子记录全部公开位置、命题值、随输出保存的引用、源内容位置、推导条件和判断。引用定位存在且内容支持才算支持；缺引用、无支持、歧义、被来源反驳均在分母内、不进分子。同一原子任一最终公开出现包含没有支持的断言，该原子不计支持；不能将一条错句与九条重复对句算90%。明确纠正单独记录，不擦除较早一轮最终公开错误。分数用整数分子/分母和精确比例比较95%，不先四舍五入；分母为0或尚未完成全表面检查时，不报PASS。提取/归一未裁决保持评分PENDING，已确定的无支持主张不能以“待核对”为由移出分母。

**关键性与完整性。** 必需事实覆盖的分母仍为预先冻结的参考事实，不与引用主张分母混用。原子关键性按执行卡事前规定的关键事实/业务决策类别标注，不能看到答案后升降级。新出现的额外来源断言仍按相同规则全部计入；命中既定关键类别的同样按关键项核对，不能把额外业务猜测自动归为非关键。每个被检查的公开文字位置必须映射到原子ID或附排除理由，防止只挑正确句计分；表面覆盖完整后才计算总分。评审者姓名/身份、争议处理和局限随结果记录；关键项人的复核仍独立PENDING，自动结果不替代它。

**事前冻结与反例。** 新执行卡在调用前绑定本节逐字文本hash、代码/P0/工具/模型与材料/rubric指纹，预先列出必需事实、关键类别及来源范围，保留冻结副本。新增同义表达按本节归一；必须改规则时另建修订，仅用于后续批次，旧批不得换规则重算后冒充原成绩。已按下列不依赖原案例答案的反例核对本节：两列类型必须为2原子；两列各0缺失必须为2原子；范围3至9必须拆下界/上界；正反关系基数不能重复计分；同一槽位先称类型X后称Y只算1原子且冲突不计支持；未注明过滤的错误总体不能用假设过滤补救；候选公式中的观察数字照常核验；0个来源主张不能直接算100%；94.995%不能四舍五入判95%；尚有未分类公开文字时不能宣布评分完成。该方法缩小事后自由度，不宣称消除了自然语言评审判断。

## 4. 样本与试验卡
