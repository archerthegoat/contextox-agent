## 2. 目标与验收

### 2.1 目标流程

在 Workbench 中跑通以下受限闭环：

1. 导入一组明确授权的资料。
2. 发起一次任务草案生成。
3. 人确认草案的精确版本与 hash，并明确开始。
4. 创建正式 Mission 和 AgentRun，调用领域工具完成受限分析。
5. 输出带来源引用的关系说明、字段定义草案和待确认问题。

### 2.2 输出粒度与证据要求

关系与字段草案至少应能说明：

- 每组表的粒度、关键字段、可观察关系，以及连接时的重复计算风险；
- 每个字段的含义、类型、粒度、来源字段、计算或筛选规则、时间口径和缺失处理；
- 每一项关系、字段和问题对应的来源版本与可恢复定位。

输出必须把观测、候选、冲突和未知分开；业务语义仍保持待批准。真实模型验收必须实际调用领域工具并使用工具返回的证据。写死样例答案、fake model 结果或聊天动画都不能替代真实验收。

路径二只交付到「草案待确认」。回答审批、正式 Contract 发布、跨任务知识复用、企业连接器和对比评测不在本轮范围；本轮不能声明 Mission completed。

## 5. 冻结边界

### 5.1 输入与来源处理

- 支持范围冻结为 UTF-8 CSV、JSON、Markdown、TXT；JSON 支持记录数组或具名表数组。
- 本轮不支持 XLSX、PDF 或目录绑定。
- 每批最多 8 个文件、合计不超过 8 MiB；单文件不超过 2 MiB；每表最多 5000 行、100 列。
- 超限必须拒绝，不能静默截断。
- 来源产生不可变 `SourceRevision`、确定性 Schema/profiling、有界样例和可恢复引用。
- 不提供任意 SQL、任意代码或任意路径读取。

### 5.2 Provider 与 Run 预算

- 沿用架构报告的单 DeepSeek 配置；不自动换模型，不新增 Provider SDK、框架或依赖。
- 生产 Provider 请求使用主进程监督的一次性 `spawn` 子进程；不新增 Provider SDK、网络服务、队列或持久 worker。
- V0 全局最多一个活动 Provider 子进程。等待执行槽位计入 Run 总时长并响应取消；预算耗尽时返回 `blocked:provider_busy`，不发送请求。
- 主进程使用 connect、first-event、idle、total、Run remaining 和 cancel 六个条件监督调用；子进程使用严格有界阶段消息。达到停止条件后先 `terminate`、有界 `join`，必要时 `kill`，并关闭、丢弃本次独占 IPC。
- 子进程不接收 Store、SQLite、领域工具或任意路径；请求正文和密钥不进入 argv、磁盘或日志。终止发生在请求可能发送之后时，结果保持 unknown，绝不自动 retry。
- 正式 Run 最多 8 轮模型请求、24 次工具调用、300 秒；单次输出最多 4096 tokens；自动重试为 0。
- Provider timeout：connect 10 秒、first-event 60 秒、idle 30 秒、total 120 秒；均受 Run 剩余预算约束。
- 首轮真实验证最多一次草案请求和一次正式 Run；追加调用必须另行确认。本 W0.0 不执行任何真实调用。
- 调用额度不是人民币费用保证。

### 5.3 持久化与迁移

- 采用 SQLite 精确识别的 v1 增量升级，使用事务保护，不重建或清空旧库。
- 未知 schema 必须拒绝；迁移先在临时库验证，不触碰用户实际数据。

## 6. 共享对象与状态边界

以下对象沿用已批准架构，精确代码级字段由主协调者在共享契约附录中设计并复核：

- `SourceRevision` / `EvidenceRef`：包含 Workspace、来源、版本、hash 和定位；
- `MissionDraftAttempt`：保存原始输入、候选版本 hash；确认后创建 Mission，显式 start 后创建 Run；
- `RunSnapshot` / 公开事件：遵循架构既有状态；重连读取快照，不伪造 delta；
- `DefinitionDraft`：包含字段、关系、证据、未决问题和版本 hash；
- `ClarificationRequest`：包含问题、原因、影响、角色和所需证据。

所有对象级 API 都必须携带 `workspace_id`。Pydantic → OpenAPI/JSON Schema → 生成 TypeScript 类型与 client 是唯一字段来源；生成文件不得手工编辑。Worker 不得自行修改共享业务状态或增加共享字段。
