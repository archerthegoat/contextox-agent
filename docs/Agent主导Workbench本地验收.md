## 4. 正式界面合成浏览器核对

通过 CUA 操作实际 React 构建与 Python API，不通过原型代替生产交互。验收使用独立临时 SQLite 和合成 CSV；以下是工程浏览器证据，不是人工验收或模型质量证据。

- 首次没有工作区：直接发消息后建立“本地工作区”，保存会话与答复。
- 选择两份精确资料，发送“先帮我看看这两张表。”，保持讨论；刷新后原消息与资料范围回读。
- 同一对话发送“我想按地区统计订单金额。”，自动形成一个任务和首次分析；中间出现实际未决的两个业务问题。
- 等待澄清期间发送“为什么需要先确认退款规则？”，正常获得讨论答复。自然语言补充退款及缺失值规则后，候选进入可修改卡片，没有自动保存批准。
- 修改候选后仅保存为 v1：没有新增 Run 或批准；一次“确认并继续”记录一个批准与一轮分析。之后普通追问直接产生下一 Run，沿用原资料，没有额外 Run 表单。
- 上述阶段数据库回读：1 个 Mission、4 个讨论回合、3 个 Run、1 个 handoff、1 个回答版本、1 个批准。刷新及查看没有增加它们。
- 手动打开订单资料期间，新讨论与续接没有抢走中间视图；“跟随当前进展”恢复联动。
- 已确认卡片默认折叠；中间以当前 Run 的既有 AnswerImpact 显示变化/仍无新结果，未虚构草案变化。编辑已批准卡片后保存为 v2，页面明确显示“已保存、尚未批准”，旧批准没有被改写。
- 任务建立后显式加入第三份地区资料，先讨论新范围，再确认已保存 v2。新版没有被旧 v1 回执阻塞，批准后卡片收起；普通追问继续成功。数据库当时回读 1 个 Mission、5 个讨论、5 个 Run、2 个 handoff、2 个回答版本和 2 个批准；最新 Run 使用 3 份来源，两个历史回答仍各绑定原来的 2 份来源。
- `8449335` 服务重启后，未关联任务的对话和精确资料预览、已关联任务的 v2 批准及三份资料范围均正常回读，没有创建重复执行。
- 运行中输入下一条草稿并停止讨论：显示取消，草稿保留。没有消息排队。
- 用 2 秒合成设置延迟，在点击发送后切换工作区：旧输入没有进入新工作区。
- 缺少模型连接：待发送内容保留；安全表单分别显示“仅保存设置”和“保存并发送这条消息”。未输入真实密钥，未调用真实 Keychain。
- 右栏鼠标拖动从 487px 调至 660px；键盘调整、双击恢复默认与刷新偏好可用。390×844 下默认对话，能切换工作区，文档宽度 390px，输入和发送按钮均在视口内。1440×900 与常规桌面宽度已检查。
- 用户复验发现右侧“＋资料”此前只切换中间资料页；当中间已经在该页或保留旧滚动位置时，视觉上像没有反应，也没有说明工作区资料不会自动纳入本轮。`60aefd6` 后，“＋资料”原地展开三份资料的已选/未选状态；选择订单资料后计数从 0 变为 1，输入区显示明确启动示例；“从本机导入新资料”把中间滚动到顶部并将焦点移到“选择文件”。
- 使用界面示例“请分析订单表中的地区和金额字段”发送后，同一会话以已选订单资料建立任务并启动第一轮分析，中间进入“等待业务回答 · 2 个已记录问题”；没有另点 Run。合成运行器改为复用生产的明确工作指令判定，避免测试示例与实际门槛不一致。

原型另外覆盖批准后启动失败恢复、未知结果核对、模型配置双动作等合成状态。生产未知/失败边界以 Store、Runtime 与 HTTP 自动测试为证据；原型通过不提升为生产浏览器通过。
