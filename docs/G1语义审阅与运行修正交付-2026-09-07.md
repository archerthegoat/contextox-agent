## 改动与理由

- agent.py：明确缺失处理是业务规则，样本无缺失不能填为已知处理；已提供单位、类型、规则不能被误标未知；候选公式保留条件；缺少最终落定所需决策应列阻塞，并给出受影响定义、负责人、证据及下一动作。批准未知不代表解决未知。
- 新 P0_RUN SHA256：ff73c255028ee367157aced3142ecf7fe8b375ba7b0ba7184384f9b396d39383。工具 Schema 不变：acaf4fda820b343181fcb19d5efa739b75f54cfa8cb15529f1d3ced74c64657d。保留旧 G1 精确 P0/schema 配对以回读历史；没有修改六维数据合同、适配器或旧校准产物。
- App.tsx：主字段结果区展示六维值及对应未知原因、证据状态与证据入口，明确业务语义待批准。已有旧详情页不重复改造。
- TaskDialogue.tsx / Path2Workbench.tsx：去除重复首读 effect；同 Workspace/Mission 被新请求取代的读取接续最新结果，原 token 继续限制状态落地。真实失败和跨作用域隔离保留；分页迟到失败不能覆盖新读状态。无消息重发或额外 Run。
- cli.py / api.py / runtime.py：官方 contextox start 的关闭阶段先唤醒并结束本应用 SSE，再遵循 Uvicorn drain 和原 lifespan Run 取消流程。全局 SSE 用 asyncio.Event，不为每连接增加等待线程；Run SSE 用停止标记及 condition 唤醒，避免丢失先发生的停止信号。

## 根因与审查

1. 语义问题是模型将观察事实当成该维度的业务值，适配器忠实保存。未添加关键词改写或审核模型；新提示词只能通过后续真实正反案例验证效果，不能提供自然语言正确性的程序保证。
2. 对话错误存在请求淘汰返回 null 被当作失败的路径。6 个可控 Promise 用例覆盖新旧顺序、两个作用域隔离及失败传播。浏览器完整隔离副本刷新后自动恢复对话；不宣称已在浏览器强制复现所有时序。
3. 退出通过官方入口复现：空闲正常，保留全局 SSE 时两次 SIGINT 均仍等待，关闭客户端才退出；第二次信号跳过轮询后仍等待 server.wait_closed。主动终止 SSE 修复此路径。集成审查拒绝每 SSE 连接占用 executor 的初稿，已改为异步全局事件并验证断连。
4. 退出修复适用于官方 CLI。外部自建 uvicorn.Server(create_app(...)) 需自行遵守对应关闭生命周期；本次不提供新服务器或部署接口，也不保证任意不可取消 Provider 的退出结果。
