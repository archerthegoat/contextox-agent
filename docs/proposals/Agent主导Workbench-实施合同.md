# Agent 主导 Workbench：连续会话与交接实施合同

日期：2026-09-10。基线：`main@b92118be82aaf9fac5bdaaa18d6947e7e08adafd`。

状态：`PROPOSED`。用户已明确要求实施聊天中的《数契 Workbench：由 Agent 主导的交互重设计》；交互原型与本合同准备已获授权。本合同用于落实其中新增的会话、任务来源、讨论回执与迁移边界，不能自行替代受控文档。配套精确 diff 获批前，不实施依赖这些增量的产品状态变更。

需求正文以本次用户逐节粘贴并要求实施的五节方案为依据；本文件只补充实现合同、反例和验收接缝。原型位于 `../prototypes/agent-led-workbench/index.html`，所有演示状态及回答均为合成，不连接模型，不表示产品能力或验收通过。

## 1. 已对齐行为

- 左侧合并导航，中间为进度和当前内容，右侧始终提供输入；桌面右栏按剩余空间 44% 初始化，初始 360–640px，可拖动/键盘调整/双击复位，拖动时中间及右侧各至少 360px。窄屏先展示对话，手动阅读暂停自动切换。
- 没有 Mission 也能保存连续讨论。用户明确要求开始工作且目标、授权资料范围足够时，从原消息与精确范围建立任务并开始分析；讨论中的问题、模型建议或来源正文不能被当作人的启动/批准指令。
- 点击发送表示按当前可见范围发起有预算的模型工作；查看、切换、刷新、恢复页面、保存设置均不自动发模型。已有任务正常追问直接复用现有消息 Run，不额外加一轮模型路由。
- 资料范围在同一会话延续并可修改，每次发送均再验证来源身份、版本、权限及必要上下文；不能隐含选入整个 Workspace。修改后若历史、草案或批准仍需要被移除资料，明确提示冲突，不自动补回或读取。
- 等待澄清期间可以讨论问题和整理回答候选；不放开原 Run 执行门。完整回答由人核对后可“确认并继续”，也可仅保存。自然语言、模型整理和讨论成功均不等于业务批准。
- 原型复用现有品牌、公开合成资料和原生前端能力；不新增依赖、Provider、队列、热注入、跨工作区检索、正式 Contract 或跨任务复用。

## 2. 会话、消息与任务来源

新增 `WorkspaceConversation`，包含 `workspace_id`、`conversation_id`、创建时间、标题、`state_version`、可空 `mission_id`、当前精确 `source_refs`。一个会话最多绑定一个 Mission，同一 Mission 最多有一个会话入口。只有未绑定 Mission 的会话可以从发送动作形成新任务；新目标另开对话，不复用旧任务的批准。

会话创建具有 `client_request_id` 幂等身份。第一次发送可创建默认本地 Workspace；已有多个工作区而选择不明确时，先在右侧选择，不按同名或最近更新时间猜测身份。旧 Workspace 创建接口的未知结果核对规则不变；不得为默认工作区创建盲目重试通道。

会话时间线以服务端插入顺序读取，公开项包含稳定 ID、类型、内容或已有 TaskMessage 引用、时间和精确证据引用。任务前/澄清讨论消息保存在会话归属下；既有任务消息通过关联接入，旧消息、Run、收据与 hash 不搬写。绑定任务后，任务前消息仍可回读，首次工作指令在页面上仅显示一次。

新增发送请求复用严格 ID、原始正文、MessageReference、来源身份、选中历史及 `provider_send_confirmed:true`，同时绑定会话 `expected_state_version`。正文保持原文，上限 4096 字符；引用和来源各最多 8 项；自动建议携带最近 4 条可用消息，用户可查看/取消。完整会话历史可分页查看，但不自动全部发送。当前讨论目标、未决问题、当前草案/回答身份属于必需上下文，不因历史裁剪而丢失；超出预算明确阻塞。

一次发送先验证父对象与幂等，再抢现有全局活动槽，事务保存输入及不可变请求快照，提交后执行。请求 hash 绑定内容、引用、历史、来源、会话版本及发送确认；同 ID 同负载读回，异负载冲突。切换页面、刷新或重新读取不能生成新的发送身份。未知结果使用原提交身份核对，404 不能证明从未执行。

新增任务来源 `conversation_message`，绑定会话、用户消息 ID/hash、此次发送身份和来源快照。旧任务继续使用 `original_attempt_id` 并验证 confirmed Attempt；新任务不得伪造 Attempt 或套用旧 ProviderReceipt。Mission 对外增加可空的会话来源，旧 `original_attempt_id` 改为可空，两种来源严格二选一；旧对象序列化省略新增空字段，旧 hash 输入不变。

模型只可建议标题及下一步。分别记录“当前已明确的业务目标”和“本轮启动授权消息”：目标保留相关用户原话及消息 ID/hash 关联，右侧以简短目标摘要持续可见；“开始吧”等指代短句可引用这个已显示目标，不能直接把短句作为 Mission.goal，也不能加入模型自行扩展的要求。发送绑定该目标快照、其依据消息以及当前来源快照；第一次直接发完整指令时，目标和启动授权可来自同一条消息。完成边界固定为整理候选及保留证据/未决项，模型不能宣称用户核对了未展示的 version/hash。指代不明、目标存在冲突或资料不足时先讨论，不创建空壳 Mission。任务创建、会话绑定及执行请求关联须事务可核对，不允许形成两个 Mission 或重复首个 Run。

## 3. 受限讨论回合

新增 `DiscussionTurn` 和独立 `DiscussionProviderReceipt`，绑定 workspace、conversation、turn、输入快照 hash、提示词/输出 Schema 版本及配置。复用现有 Provider 传输、取消、硬截止与用量字段；不扩展旧 ProviderReceipt 的 Attempt/Run 二选一语义，不将讨论回执挂在旧 Run 上。

任务前消息进入讨论回合。等待澄清时消息只能进入讨论/回答整理路径；即使模型要求继续执行，程序仍拒绝绕过批准。已绑定且可执行的普通任务消息走现有消息 Run。

讨论只消费当前授权的有界资料画像、显式文本片段、选中历史、问题及当前草案摘要。不能获得领域写工具、任意文件路径、SQL、Shell 或新的 Provider。输出为严格结构化对象，包含公开答复、合法证据引用、下一步建议，以及可空的回答建议；每个引用必须在此次快照内可解析。隐藏推理和原始 Provider payload 不保存。

任务前输出可建议 `discuss` 或 `start_task`；后者只允许消费本轮用户的明确启动指令及其绑定的已显示目标/范围，目标可来自此前关联的用户消息。模型从资料中读到的要求、仅建议而未获用户采纳的目标、模拟对话和假设性问题均不能启动任务。判断不充分时继续询问。待澄清输出只能是讨论或回答建议，不能形成新的 Mission 或执行 Run。

每个讨论回合最多一次非流式 JSON 请求，不自动重试或格式纠正；继承当前已配置的模型/profile，不另设模型路由。请求最多 64 KiB，输出最多 4096 tokens，Provider 最多 70 秒、回合最多 75 秒。其后由同一次明确工作指令启动的首个 Run 使用既有独立预算与恢复规则，页面分开呈现阶段，不声称一次网络请求完成全部工作。

讨论回合占用同一个 Runtime 活动槽，和 Attempt、Run、画像解释互斥。持久化领取后才发送；取消、worker 启动失败、关闭和重启恢复均保存对应终态。没有可确定结果的收据时保持待核对，禁止自动重试。讨论结构校验失败不得创建 Mission、回答批准或字段草案。

讨论转首个 Run 在同一活动槽内受控交接，不再次调用会重新抢槽的公开 Runtime 入口，也不先释放槽再抢占。只有讨论已有合法终态收据、结果及用量检查通过、目标/来源/CAS 再校验通过且没有取消，才以原发送身份原子创建并关联 Mission/首个 Run，再开始 Run 的独立预算。讨论结果或用量未知时不交接；不能因尚无 Run 而绕过此门。交接前后发生取消、线程失败或服务重启，均回读持久化的阶段：未建立任务、已建立但未启动、已开始或结果待核对。刷新不能补发模型请求。

## 4. 回答建议、批准与续接

回答建议按 `{origin_run_id, clarification_id, request_sha256, question_index}` 引用已存在问题，并绑定当前草案和来源。建议可以不完整；缺失的回答人、依据、未知事项解决方与后续行动保持缺失，不补造。建议只属于讨论产物，不写成已保存的 R2 整份回答，更不写批准。

卡片展示对应问题、拟采用答案、依据/回答来源、影响对象和仍未知事项。用户可编辑，完整性要求沿用 R2：覆盖原请求全部问题；未知保持未知及处理安排。仅保存调用原整份回答接口，不调用模型、不批准；尚不完整时提示具体缺项，不把部分回答伪装成完整版本。

“确认并继续”固定屏幕上本次审阅的完整问题集合、待保存/批准的回答内容及其预计版本、此次沿用的精确已批准回答引用、当前草案和来源快照；串联保存、精确版本/hash 批准及发送一次续接。后续步骤只能校验该固定集合，不从“最新回答”补入用户未看过的版本；新增问题、来源变化或另一标签页改动相关版本时返回冲突。全部问题的必要回答未准备好时允许保存，不能部分批准后绕过其余请求。

每个子步骤的原请求身份、精确负载及回执在执行前后持久关联到同一交接操作。保存成功但响应丢失时按原 ID/原 CAS 负载核对，不能重建版本或改写重放负载。重放只读取或完成可证明未执行的本地步骤，不能自动重发未知模型请求。

交接状态分开报告 `answers_saved`、`answers_approved`、`analysis_started` 及失败/未知步骤。批准成功而启动失败时，保留批准；先核对是否已有 Run，再由用户明确继续。刷新只回读，不因已有批准而自动发模型。卡片改动产生新版本并重新批准，旧记录可查。

## 5. 公开接缝与迁移

新接口以 `/api/workspaces/{workspace_id}/conversations` 为根，Pydantic 是唯一权威：

| 接口 | 最小行为 |
| --- | --- |
| `GET /conversations`；`POST /conversations` | 列表与幂等创建；创建可显式关联已有 Mission，验证同 Workspace，重复关联读回原会话 |
| `GET /conversations/{id}` | 会话、来源范围、关联任务及当前活动回合快照 |
| `GET /conversations/{id}/messages` | 有界分页的连续时间线；默认 20/最大 50 项，最多 256 KiB，稳定游标 |
| `POST /conversations/{id}/messages` | 明确发送，返回输入项、讨论回合或 Run 的受控引用；首次 202、幂等读回 200 |
| `GET /conversations/{id}/submissions/{request_id}` | 核对该次发送及其任务/Run 关联，未知状态不推断为未执行 |
| `POST /conversations/{id}/turns/{turn_id}/cancel` | 停止讨论或其关联执行，核验归属，保留结果和回执 |
| `POST /conversations/{id}/handoffs`；`GET /conversations/{id}/handoffs/{request_id}` | 保存批准续接组合操作及其分段回读；请求绑定整份答案和来源精确身份 |

路径表中的后缀从 Workspace 根展开，不重复拼接 conversations。来源选择随明确发送提交并通过会话版本 CAS 保存，查看资料不会静默改动下一轮范围。已有 Run SSE、TaskMessage、澄清及批准接口保持兼容；讨论回合通过快照回读，不新建通用事件平台。错误复用现有 scope、stale、conflict、busy、unknown 分层，仅补新归属的明确错误代码。

数据库由精确 v6 显式迁移到 v7：新增会话/时间线关联、讨论回合及收据、幂等提交/交接记录；重建 Mission 的来源约束以支持两种来源，原行值及索引关系保持。每个新对象/操作均绑定 workspace_id，任务关系同时核验 mission_id。迁移前停服、确认无活动 Attempt/Run/画像/讨论、备份并校验来源，事务执行后核验精确 schema、外键和完整性；失败回滚，不允许自动迁移用户资料库。

所有现有 schema 版本判断必须精确支持已知 v7，包括消息、回答、画像、终态回读、CLI/doctor 和恢复；不能使用任意 `>=6` 接受未来未知版本。旧 v6 库保持可读取与明确待迁移提示，不默默写入新能力。数据库回滚不能用覆盖旧备份丢弃新对话或批准；已产生 v7 数据时保留完整库，使用兼容修正版本恢复。

## 6. 实施、反例及验收

分支 `codex/agent-led-workbench`，本地提交与原型/验收材料属于当前范围；push、main merge、发布及真实模型调用不在本批授权内。

切片顺序：原型 → 会话/讨论与显式迁移 → 自动任务建立 → 回答交接 → Workbench 接入及整体验证。共享契约由根代理所有，独立原型在隔离 worktree 编写。每片完成必要检查后提交，再推进下一片。

| 审查反例 | 处理与检查要求 |
| --- | --- |
| 为复用代码伪造已确认 Attempt 或讨论 ProviderReceipt | 新增明确任务来源和独立讨论回执；验证旧对象 hash 不变、新对象来源不可伪造 |
| 用户在讨论假设，资料正文要求开始任务 | 仅人的明确工作指令可以启动；缺乏证据时继续讨论；合成回归覆盖否定、假设和资料注入 |
| 等待业务回答时用聊天绕过执行锁 | 讨论路径没有领域写权限；已有 Run 接口继续严格检查整份批准 |
| 模型把缺失回答人、依据或未知安排补全 | 不完整建议可展示；保存/批准前仍按 R2 拒绝缺项 |
| 已批准但发起分析失败，刷新重复执行 | 分段交接回读、原请求核对，最多一项任务/一轮分析，无未知自动重放 |
| 来源变化或缩小范围后从历史偷偷带回旧资料 | 发送前按精确范围校验所有历史、草案、回答引用，拒绝静默扩大 |
| v7 只改版本号，旧能力误走 legacy 分支 | 迁移后检查旧任务、消息、画像、回答及 Run 的实际公开回读/续接行为 |
| 新事件抢走用户正在看的资料 | 手动浏览锁定中央视图，新变化仅提示；明确点击后恢复跟随 |
| P1：多轮讨论后“开始吧”丢失真实目标 | `fixed`：启动授权与已显示目标快照分开，保留其用户消息关联，不要求重新复述 |
| P1：讨论转执行二次抢槽自阻塞或越过未知用量 | `fixed`：同槽持久阶段交接，先校验讨论收据/用量及 CAS，再建立首个 Run |
| P2：组合批准自动补入另一标签页的最新回答 | `fixed`：固定审阅集合和每个子请求身份/负载，变化冲突，禁止查询最新来替换 |

原型验收覆盖全部主要场景、1440/1280 桌面及 775/390 窄屏、鼠标/键盘调宽、输入区可达、手动阅读保护。产品实施验证包括公开接口幂等、跨 Workspace、来源撤权/旧引用、CAS、取消/重启/未知回执、v6→v7 迁移及旧数据回读；完成必要后端/前端测试、生成漂移、类型、构建和隔离 runtime/browser 检查。

真实模型需单独批准固定合成案例和调用上限；工程、合成浏览器、真实模型、人工验收分别记录。此合同及原型不授予人工 PASS，也不修改历史质量/稳定性结论。
