# G0 实施合同 v1

2026-09-07。基线：`main@636adf4`。参数适配层方向已获人同意；本稿为具体实现合同，架构精确补丁尚未应用，G1 尚未开始。

本文取代旧 G0 草案的待选方案与分支说明。旧研究、试跑及批准回执保留；本次不扩展模型调用、输入资料或远端交付范围。

## A. 交付目标与权限

在现有七个领域工具与 Store 之间实现确定性参数适配，减少模型复制身份、版本和 unknowns 的工作。模型继续负责业务含义、推断、证据选择与未知理由；程序不得补业务默认值、批准业务结论或完成 Mission。

实现使用 `codex/r1-g1-tool-contract`，从经核验的统一 main 建立，主 Agent 为写入负责人。批准本稿的实现范围包括局部代码、生成类型、必要测试、架构批准文本落地、本地 checkpoint 和检查通过后的本地 main 合并；不包括 push、部署、依赖升级、真实 Provider 调用或 R2 新持久对象。紧密耦合实现串行进行，不默认增加子 Agent/worktree。

## B. 参数与引用合同

七个工具名称不变。新增模型侧 Pydantic 输入类型，工具 JSON Schema 从类型生成；适配到现有领域 Pydantic 对象后再次严格验证，再进入 Store。不手工修改生成的 API/types。

句柄统一为 ASCII 标识，长度 1..64，不携带文件路径或业务值。运行内注册表将 source/table/column/evidence/draft 句柄映射至当前 Workspace、Mission、Run 和精确来源版本/定位或草案 version/hash。类型前缀不提供权限；完整作用域和来源准入必须重新核对。禁止跨 Run、模糊匹配、猜测缺失对象和解析为当前 latest。

| 工具 | 模型侧输入 | 确定性输出/处理 |
| --- | --- | --- |
| list_sources | 空对象 | 已选来源的 source_handle、名称、媒体类型、解析状态、有界真实范围/表句柄；不能列入其他授权来源之外的对象 |
| read_source | source_handle + 原 EvidenceLocator | 映射 revision，严格有界读取；输出 evidence_handle、片段和实际定位；错误范围不裁剪 |
| inspect_dataset | kind=table + table_handle，或 kind=relationship + left/right_table_handle | 既有 profiling 和样本限制；结果注册合法表、列、证据句柄 |
| update_definition_draft | draft_token + fields + relationships + unresolved_items | 精确 CAS 与现有按 key upsert；未提供的字段/关系保留；unresolved_items 按当前 Store 行为，不额外发明合并规则 |
| create_clarification | draft_token + questions | 问题沿现有结构，证据用 evidence_handles；映射精确版本后沿当前等待人工终态 |
| submit_for_review | draft_token | 精确候选冻结；不批准、不完成 |
| finish_run | outcome=partial + reason + evidence_handles | 原有公开答复与终止收据规则；reason 最大 4096 字符 |

字段输入：field_key、name、semantics、source_column_handles、evidence_status、evidence_handles。semantics 六个必需键为 meaning/value_type/grain/rule/time_basis/null_handling。每项必须是 `{value:值, unknown_reason:null}` 或 `{value:null, unknown_reason:非空理由}`，不允许两者同空或同时有值。value_type 的值沿用 Key（1..128，含既有字符验证）；其他值沿用 Text（最大4096）；unknown_reason 为非空、最长4096文本。适配器生成原属性和 exact unknowns，不能填值。

关系输入沿用 relationship_key、observed_cardinality、join_rule、grain_notes、evidence_status、risks、unknowns；left/right 改为表句柄，source_refs 改为 evidence_handles。问题沿用 question、why_needed、expected_answer_type、suggested_owner_role、related_definition_paths、evidence_requested、examples_or_options、blocking_impact，source_refs 改为 evidence_handles。原领域最大项数与校验全部保留；此版不添加领域 Schema 原本没有的业务要求。

输入类型全部 extra=forbid，不做字符串到数字等宽松转换。observed 必须有合法证据；合法证据位置不保证模型事实正确，语义质量由独立 rubric 验证。

初始 draft_token 显式表示该 Run 看到的无草案状态。成功写入返回新 token；旧 token 不升级。同批只允许一个草案写入，禁止同批预测下一版本；终态工具仍须独占一批。并发变化产生明确冲突，新版本需模型重新看到后重新提议。

### 关联列输入补充（已批准，2026-09-07）

inspect_dataset 的 kind=relationship 输入，除 left_table_handle/right_table_handle 外，增加必填 left_column_handles/right_column_handles。RelationshipCandidate 模型输入的 left/right 表句柄同样配套这两个必填列表。每个列表包含 1..100 个不重复列句柄，两侧长度相等，顺序确定关联键配对；解析后构造原 TableKey.columns。每个列必须属于对应表和当前 Run 的已选来源；禁止程序按列名相似或样本值自动选择。领域原有检查继续执行。仅有表句柄不足以形成有效关系提议，缺失关联列应作为可纠正的参数拒绝，不执行本批。

## C. 来源覆盖与上下文

开始 Run 时提供一次当前任务快照、来源清单、已存在草案及句柄。每轮不再追加完整旧快照；工具结果提供本次片段或有界结果，版本更新返回必要差异。需要刷新当前快照时替换应用快照，不删除 Provider 要求的 assistant/tool 历史及 reasoning_content。

目录中的文本行数、CSV 数据行数及 JSON 表/定位来自当前解析工件，不使用固定 1..20 或 1..10 作为所有文件的首次范围。空文件没有合法非空读取范围，保持明确状态。不会因为工作集设计而访问未选来源或自动扫描其他路径。

运行内覆盖记录以成功读取为依据，区分列出、读取成功和读取失败。完整资料不在预算内时说明未覆盖部分，不能谎称读完。原七行任务说明是否被正确理解属于公开回归断言，不把其答案写入程序。

## D. 批次预校验、错误与计数

先检查完整 Provider 响应、合法工具名、call_id 非空且当前 Run 全局不重复、终态独占、预算，再解析整批参数并执行纯校验。参数错误时本批所有领域操作均不执行，不执行其中合法子项。来源权限问题、协议问题、重复身份和未知写入结果仍按原失败关闭处理。

对完整响应中“已知无领域写入”的参数格式/字段一致性错误，允许最多两次模型纠正，计入原 8 次模型请求及 24 次工具提议上限；第三次此类拒绝结束失败。HTTP 自动重试仍为 0。定位拒绝与 CAS 冲突也计入同一恢复额度，不能无限绕预算。

模型临时反馈：`{ok:false,error:{code,recoverable,paths,expected_shape,effect:"none"}}`。最多五条白名单属性路径，说明合计不超过2048字符；路径不能包含原始值、业务 key 或任意错误 repr。整批中未出错的调用用 batch_rejected_no_effect 告知被连带拒绝。每个原 call_id 得到对应反馈；原始参数与隐藏推理不持久化。

**复用现有事件，不新增事件枚举。** 对执行前整批拒绝，只记录每个合法 call_id 的 tool_failed，error_code 为 `tool_arguments_invalid_no_effect` 或 `batch_rejected_no_effect`。不伪造 tool_started、tool_completed 或 ToolReceipt。Workbench 对这两个码显示“调用已拒绝，未执行”，未知旧客户端仍能显示通用失败码。

合法执行继续沿用 tool_requested → tool_started → tool_completed/failed。现有事件 ordinal 与 Store 的连续 ToolReceipt ordinal 继续指向实际领域执行序列；不拿预校验拒绝占用该序列。Agent 另维护提议总数（含整批拒绝），新协议下每批先核对是否会超过24；超限立即终止且零执行。超限批数量可记录安全计数诊断，但不伪造收据。

两种计数不能混用：ToolReceipt 个数仍表示进入领域工具并形成回执的次数；提议数用于 Agent 预算。崩溃/取消后不恢复模型循环，也不以已形成回执数重算额度来续跑旧 Run。所有曾接受的 call_id（包括拒绝批）放入当前 Run 的去重集合。

写入结果未知、取消及 Provider 未知不能进入纠正路径；保留实际状态，不自动重试。不改变同一 Mission 的 previous_outcome_unresolved 限制。

## E. 观测与兼容

继续使用现有 ProviderReceipt、ContextPacketManifest、ToolReceipt、RunEvent 领域结构及 SQLite DDL。本版不新增事件类型、不改数据库 schema version、不对旧数据进行迁移。工具协议与 P0 指纹更新，旧精确配对继续支持历史读取，不组合独立白名单。

安全诊断使用固定白名单：阶段、请求序号、应用快照/历史/tools 字节、提议/执行/纠正计数、有效响应时间、finish reason、已观察到的 Provider ID、已知用量和未知状态。它们是本次运行诊断，不伪装成新增持久账本；持久用量和完成状态仍来自原收据。不得保存原始 Provider payload、用户资料值、模型参数全文或隐藏推理。

需验证新程序能回读旧预算、旧草案/hash、旧事件、旧指纹；原始记录不重写。旧程序能够解析既有事件形状，不代表能够理解新的工具指纹，因此不承诺旧二进制完整打开包含新 Run 的库。回退应使用支持两代指纹的修正版本，或在授权的数据恢复方案中使用运行前备份；不得删新回执来强行回退。

临时句柄不进入跨 Run 业务对象，重启后不恢复其会话；正式字段、关系、澄清继续保存完整领域引用。若实施发现必须变更 DDL/事件结构/恢复语义，停止该部分并展示实际差异，不能自行扩大本合同。

## F. R2 与验收

R2 输入仍为正式 DefinitionDraft、ClarificationRequest 和将来单独获批的回答快照。整份回答一起批准、允许批准未知记录但问题未解决、解决方/证据/下一动作、原请求新版本重批均保留。本批不实现 R2 新接口或迁移。

G1 最小公开接缝证伪集合：

1. 有效候选经适配与原领域对象等价；六维未知无缺漏/多余/重复；非空错误或非法 Key 拒绝，不补业务值。
2. 七行/短CSV/空文件从真实目录得到合法起点；跨Workspace/Run、未选来源、失效来源与伪造句柄拒绝。
3. 一次结构错误可纠正并形成真实产物；连续三次拒绝结束；拒绝批中其他合法写入也未执行。
4. 旧 token 冲突而不升级；同批预测版本拒绝；漏给 token 不默认为 latest。
5. 拒绝不生成假 ToolReceipt；实际执行 ordinal 仍连续；拒绝与实际调用共同受24次提议预算限制。
6. 取消、重启、未知副作用不自动重发；已存在关系不会因后续非法字段而丢失。
7. 新旧指纹/预算/草案/hash/事件回读一致；Schema漂移检查通过；前端能显示拒绝且未执行。
8. 假 Provider 只使用模型公开输入和工具输出，不查询 Store 获取答案或版本。合法 partial 但遗漏单位等反例在独立语义 rubric 中失败。

通过必要Python测试、前端测试、类型与生成漂移、构建、临时数据运行和差异/隐私检查后，允许形成 G1 本地工程交付。它不等于 G2 真实质量或人的验收。

## G. 执行与停止边界

首次真实校准仍沿旧试验卡的一个完整案例、至多17次模型请求构想；本合同不授权调用。精确G1构建、材料hash、当前模型身份与费用封顶必须在调用前形成独立可执行卡。正式27案例尚未开跑。

本地整合只包含批准的架构文本与本合同范围；保留失败证据和旧分支，不推送或删除远端分支。开发路径图已批准，本次不再改动。G1检查失败时先修复获准范围内问题，未通过不能合并。

## H. 主审结论

已复核旧Store的 ordinal=len(receipts)+1，故弃用“让预校验拒绝占用实际执行ordinal”的做法，改为现有tool_failed与独立提议计数。已复核事件枚举与回读，选择保留事件形状；这解决了原G0审查F02-F05中新增事件迁移的风险，但旧二进制识别新指纹的回退限制仍明确保留。

方向选择已完成。本合同和随附架构精确补丁经批准后，G0的实现边界可冻结，进入G1；真实评测准备与费用卡仍独立推进。没有未展示的新框架、Provider、业务默认值或自动批准。
