## 2. 通用类型与校验

下文是精确字段清单；同一对象不能额外塞自由 dict 或预留字段。Pydantic extra=forbid；所有对象级入口按 workspace_id 和 parent identity 再校验。现有 Workspace、EvidenceStatus（检查证据状态）、WorkspaceError、ApiRequestError 和既有三个 Workspace 路由不改语义。

记号：
- ID：canonical lowercase UUIDv4；服务端对象 ID 由服务端产生。client_request_id 是客户端为一次显式 Start 产生的独立 ID，不可作为任何业务对象身份。
- Hash：64 位 lowercase SHA-256；UTC：带时区的 UTC 时间。
- Key：1–128 个 Unicode code points 的非空标识，不接受控制字符；它不具有文件路径或 SQL 含义。
- Text：不超过 4096 个 Unicode code points；短标题不超过 160；原始用户输入不超过 16384。说明文字不暗含业务事实批准。
- Count：严格非负整数，bool/小数/数字字符串不能冒充计数。
- T?：字段存在但可为 null；数组默认必须存在，除特别说明可为空。请求里不接受未列字段；可空不等于任意省略。
- 标注“最多”的输入超限要明确拒绝，不能静默截断。样例/摘录的展示截断必须带 truncated=true，不改变原字节。

新增的具体展示/资源上限（本版本提出，待本次确认）：每表最多 5 个样例行；每个样例单元格最多 256 code points；每个来源摘录最多 8192 code points；每次最终 Provider HTTP JSON 请求（含 P0、工具定义和当前 Run 临时 transcript）UTF-8 编码不超过 256 KiB；单文件最多 16 个命名表；一个 Run 最多显式选 8 个来源 revision；输入 HTTP body 最多 12 MiB（同时仍按解码原字节执行 2/8 MiB 限制）。字段/关系草案各最多 100 项；一次澄清最多 20 个问题；最终用户可见摘要最多 32768 code points。超出支持能力明确 blocked，不伪造完整结果。

版本/hash：
- 来源 sha256 只对原始上传字节计算。
- MissionDraftPayload、DefinitionDraft 的 canonical payload 使用 JSON-mode、UTF-8、sort_keys、紧凑 separators、ensure_ascii=false、allow_nan=false；没有 binary float 字段参与精确数值传递。
- 对象自己的 hash 字段、时间和 UI 展示状态不参与 payload hash；有序字段/关系/问题数组保留顺序。具体 canonical payload 在下文逐一列明。
- 版本/hash 由服务端产生，确认和更新只提交 expected 值，不能信任模型自报的“已确认”。

## 3. W1 使用的来源和证据模型

媒体类型仅 text/csv、application/json、text/markdown、text/plain；UTF-8。原名只用于展示，不参与落盘路径。格式、单文件 2 MiB、批次 8 文件/8 MiB、每表 5000 行/100 列沿用总方案。

```text
SourceIdentity = {workspace_id:ID, source_id:ID, revision_id:ID, sha256:Hash}
SourceRevision = SourceIdentity + {
  original_name:Key, media_type:四种媒体类型, byte_size:Count,
  observed_at:UTC, effective_time:UTC?,
  permission_status:read_allowed|denied|unknown,
  parse_status:pending|ready|partial|blocked|failed, parser_version:Key
}
EvidenceLocator =
  {kind:csv_rows, row_start:正整数, row_end:正整数, column:Key?}
  | {kind:json_pointer, pointer:string}
  | {kind:text_lines, line_start:正整数, line_end:正整数}
EvidenceRef = SourceIdentity + {locator:EvidenceLocator}
SourceIssue = {code:Key, locator:EvidenceLocator?, message:Text}
SampleCell = {
  column_name:Key, value_kind:missing|null|string|integer|decimal|boolean|json,
  text:string?, truncated:boolean
}
SampleRow = {row_number:正整数, cells:SampleCell[], source_refs:EvidenceRef[]}
ColumnProfile = {
  name:Key, observed_types:Key[], missing_count:Count, null_count:Count,
  distinct_count:Count, numeric_min:string?, numeric_max:string?
}
TableProfile = {
  table_id:string, row_count:Count, columns:ColumnProfile[],
  duplicate_row_count:Count, sample_rows:SampleRow[], source_refs:EvidenceRef[]
}
SourceArtifact = {
  source_ref:SourceIdentity, parser_version:Key,
  parse_status:ready|partial|blocked|failed,
  tables:TableProfile[], text_line_count:Count?, issues:SourceIssue[]
}
SourceExcerpt = {source_ref:EvidenceRef, text:string, truncated:boolean}
TableKey = {source_ref:SourceIdentity, table_id:string, columns:Key[]}
RelationshipProfile = {
  left:TableKey, right:TableKey,
  left_rows:Count, right_rows:Count,
  left_distinct_keys:Count, right_distinct_keys:Count,
  left_null_keys:Count, right_null_keys:Count,
  matched_distinct_keys:Count, unmatched_left_rows:Count, unmatched_right_rows:Count,
  prospective_join_rows:Count,
  observed_cardinality:one_to_one|one_to_many|many_to_one|many_to_many|unknown,
  source_refs:EvidenceRef[], limitations:Text[]
}
```

- CSV 定位为数据记录的 1-based 闭区间，不是物理换行号；列名必须存在，重复/空表头或行宽不齐显式失败，不猜列对应关系。
- JSON pointer 采用 RFC 6901：空指针表示根，数组下标 0-based，~0/~1 转义；非法/越界 locator 拒绝；JSON 重复对象键、非有限数和不合法数值均拒绝，不能由解析器悄悄覆盖。JSON 表根是记录数组，或对象中具名的记录数组；其他片段明确报告 unsupported，不把任意 metadata 对象当新获准格式。可保留确定成功表并标 partial，不能静默忽略失败片段。
- table_id 是逻辑表根的 JSON pointer：CSV 和 JSON 数组根均为 ""，命名表为对应转义 pointer。它不包含文件路径。
- Markdown/TXT 用 1-based 闭区间行定位；range 必须 start<=end；摘录超展示上限可截断并标明，但 locator 始终指向原 revision。
- SampleCell 的精确数值、前导零 ID 用文本传递；missing/null 的 text 为 null，空字符串不是 missing。数字不经 JS number 往返。numeric_min/max 只在可无损解释的数值观测上填写；CSV 的词法特征不自动升级成业务类型。
- SourceArtifact 只回报解析结果，不授予权限、不改 SourceIdentity。Store 将其映射为 SourceRevision 当前解析状态。
- 关系检查只针对显式键做计数：任一键分量 missing/null 的行不连接；不跨类型、大小写或格式自动归一化。零匹配时 cardinality=unknown；重复膨胀和未匹配均保留，不推断企业/门店或业务主外键已批准。

W1 精确入口（均无文件/数据库/网络操作）：
```text
parse_source(revision: SourceRevision, content: bytes) -> SourceArtifact
read_source_fragment(revision: SourceRevision, content: bytes,
                     locator: EvidenceLocator) -> SourceExcerpt
inspect_relationship(left: TableKey, left_revision: SourceRevision, left_content: bytes,
                     right: TableKey, right_revision: SourceRevision, right_content: bytes)
                     -> RelationshipProfile
```
每个入口核验传入身份、hash、byte_size、限额；关联双方 Workspace 不同即拒绝。元数据不符不返回伪造成功 Artifact。W1 可在 sources.py 定义有界 SourceInputError(code)，由 W0 映射领域错误，不把原始异常或源正文传出。

## 4. Mission 草案、确认和 Run

```text
MissionDraftPayload = {
  title:短标题, goal:Text, completion_criteria:Text[1..20], scope_notes:Text[0..20]
}
MissionDraftAttempt = {
  workspace_id:ID, attempt_id:ID, created_at:UTC, original_input:string,
  status:queued|running|ready|confirmed|blocked|failed|cancelled,
  candidate:MissionDraftPayload?, candidate_version:正整数?, candidate_sha256:Hash?,
  provider_receipt_id:ID?, mission_id:ID?, error_code:Key?
}
Mission = {
  workspace_id:ID, mission_id:ID, created_at:UTC, state_version:正整数,
  status:active|waiting_for_human|blocked|completed|cancelled,
  title:短标题, goal:Text, completion_criteria:Text[], scope_notes:Text[],
  original_attempt_id:ID, source_refs:SourceIdentity[]
}
RunBudget = {
  max_model_turns:8, max_tool_calls:24, max_elapsed_ms:300000,
  max_output_tokens:4096, max_retries:0,
  connect_timeout_ms:10000, first_event_timeout_ms:60000,
  idle_timeout_ms:30000, total_timeout_ms:120000, max_context_bytes:262144
}
RunSnapshot = {
  workspace_id:ID, mission_id:ID, run_id:ID,
  status:queued|running|waiting_for_human|partial|completed|blocked|failed|cancelled,
  created_at:UTC, started_at:UTC?, finished_at:UTC?, budget:RunBudget,
  source_refs:SourceIdentity[], draft:DefinitionDraft?,
  clarifications:ClarificationRequest[], last_sequence:Count,
  terminal_receipt:TerminalReceipt?, final_output:string?, error_code:Key?
}
MissionSnapshot = {
  mission:Mission, draft:DefinitionDraft?,
  clarifications:ClarificationRequest[], latest_run:RunSnapshot?
}
```

草案 hash 的 canonical payload 就是完整 MissionDraftPayload 四字段；原始输入在 attempt 创建时不可变，首次版本为 1。ready 必须具有 candidate/version/hash/ProviderReceipt；confirmed 必须有 mission_id。失败不能带“确认成功”的 mission_id。

一次 attempt 仅 P0+该原始输入、无来源和 tools、最多一次 non-streaming Provider 请求。确认必须绑定 candidate_version/hash 和显式来源 identities；相同确认重放返回原 Mission，同 attempt 不同 payload 返回 conflict。确认不创建 Run。首次 MissionMessage 引用原始输入，不复制隐藏 transcript。

Start 是另一显式动作；校验 Mission state_version、完全匹配的来源 identities、当前权限和外发确认。client_request_id 同 Workspace/Mission 内同 payload 重放只读回原 Run，不再发 Provider；不同 payload 同 ID 为 conflict。另一 active Run 已存在时拒绝。RunBudget 是固定上限，HTTP/模型不能提高它。

本路径没有合法的 Mission completed 通道。保留架构的状态全集便于准确表示，但不能生成 completed 成功结果；自然 stop、agent_end、确认、模型文字和 submit_for_review 都不是 Mission 完成。

## 5. 字段、关系草案和待确认问题

现有 models.EvidenceStatus 是“检查证据”状态，不重命名、不复用。新增 StatementEvidenceStatus=observed|candidate|conflict|unknown；observed 只描述有证据的数据观测，不是业务批准。

```text
ColumnRef = {source_ref:SourceIdentity, table_id:string, column:Key}
UnknownItem = {property_path:Key, reason:Text}
DefinitionField = {
  field_key:Key, name:Key, meaning:Text?, value_type:Key?, grain:Text?,
  source_columns:ColumnRef[], rule:Text?, time_basis:Text?, null_handling:Text?,
  evidence_status:StatementEvidenceStatus, source_refs:EvidenceRef[], unknowns:UnknownItem[]
}
RelationshipCandidate = {
  relationship_key:Key, left:TableKey, right:TableKey,
  observed_cardinality:RelationshipProfile 的枚举,
  join_rule:Text?, grain_notes:Text?, evidence_status:StatementEvidenceStatus,
  source_refs:EvidenceRef[], risks:Text[], unknowns:UnknownItem[]
}
DefinitionDraft = {
  workspace_id:ID, mission_id:ID, draft_id:ID, version:正整数, sha256:Hash,
  status:draft|in_review, semantic_approval:pending,
  fields:DefinitionField[], relationships:RelationshipCandidate[], unresolved_items:Text[]
}
ClarificationQuestion = {
  question:Text, why_needed:Text,
  expected_answer_type:text|number|boolean|date|enum|range|field_selection,
  suggested_owner_role:Key?, related_definition_paths:Key[],
  evidence_requested:Text[], examples_or_options:Text[],
  blocking_impact:blocking|non_blocking, source_refs:EvidenceRef[]
}
ClarificationRequest = {
  workspace_id:ID, mission_id:ID, run_id:ID, clarification_id:ID,
  draft_version:正整数, draft_sha256:Hash, status:awaiting_answer,
  questions:ClarificationQuestion[1..20]
}
```

草案 canonical payload 为 fields、relationships、unresolved_items 三字段；身份/version/sha/status/semantic_approval 不混入 hash。字段和关系 key 在各自数组内唯一。任一字段的可空语义维度为空，必须有对应 unknowns；不存在的规则不得自动补业务默认值。缺来源时明确 unknown/candidate，不能凭同名列写 observed。

update_definition_draft 按 field_key/relationship_key 做显式 upsert：提交的对象完整替换对应候选项，未提交项保留；本轮不提供删除或通用 patch。unresolved_items 为本轮完整列表。每次写入生成不可变新版本；首次 expected_version=0、expected_sha256=null，后续必须精确匹配当前版本。旧版本冲突不写入。冻结为 in_review 后本轮不继续修改，不办理回答或业务批准。

  outcome:waiting_for_human|partial,
  draft_id:ID?, draft_version:正整数?, draft_sha256:Hash?,

ContextManifestInput = {

  draft:DefinitionDraft?, clarifications:ClarificationRequest[]

```

所有 turn_index 从 1 开始；attempt 固定为 1，正式 Run 最多 8。ProviderConfigSnapshot 沿用已批准固定 endpoint 和默认 Flash/人工 Pro，不提供新的客户端配置入口；P0 hash 对应实际本轮指令版本。

ProviderReceipt 的 attempt_id 与 run_id 二选一；run 模式必须同时带匹配的 mission_id。succeeded 必须有 input/output usage；缺 usage 记录 provider_usage_unknown、结束请求并阻止下一次调用。attempt 模式 manifest/tool hash 为 null；正式 Run 的 manifest ID/hash 与 tool hash 必须存在并校验一致。receipt 不含 upstream raw request/response、密钥、prompt、源正文、异常 body 或 reasoning_content；没有新 Provider 配置入口或 SDK。

Manifest hash 是自身除 sha256 以外字段的 canonical JSON hash，只保存 metadata，不保存完整 prompt。draft ID/version/hash 同时为空或同时有值；所有嵌套身份与可信 Workspace/Mission/Run 对齐。

W2 每轮只读取得一致 ContextSnapshot，编译/裁剪后提交 ContextManifestInput；Store 复核当前权限、state_version、草案/来源版本与选中的收据，再赋 manifest ID/hash 并持久化。该检查是发送前的领域校验，随后 W2 再检查取消与时间/字节预算才发请求。发送之后的撤销不能追回已经发送的字节，只能尽力中断，这是实际限制。W2 的 ContextPacket 和临时 transcript 在 agent/provider 模块内构造，不对 HTTP 暴露；P0 与 evidence-only 内容分开，未批准的 Context/MEMORY 不加载。保护当前输入、目标、权限、待确认问题和活动工具对，不因预算不够截断；不能保留则 blocked:context_budget_exceeded。按最终请求 UTF-8 字节检查 256 KiB 上限，不用字符数冒充 token 或人民币预算；只记录计数，不记录请求原文。所有停止态（包括 waiting_for_human/partial/blocked）都丢弃临时 transcript，不跨 Run 复用。

finish_run({outcome:partial, reason:Text, source_refs:EvidenceRef[]}) -> TerminalReceipt
```

TableKey/EvidenceRef 内的 workspace_id 是被校验的证据身份，不是模型切换 Workspace 的能力；整个调用始终按可信 Run 的 Workspace 重新核验。search_context 本轮不注册，不提供假知识库；finish_run 不接受 completed。

DomainToolCall={call_id:Key,name:上述工具名,arguments:对应严格参数}。RunToolResult={call_id:Key,status:succeeded|rejected,output:该 name 对应结果或 DomainRejection,tool_receipt:ToolReceipt,terminal_snapshot:RunSnapshot?}；实现为严格判别模型/明确映射，不使用无约束 dict。result.output 是获准的模型工具数据，不写普通日志/SSE。

先完成整批 JSON/Pydantic/allowlist 校验，再由 Store 完成整批只读权限/版本/状态检查；全部通过才串行执行。业务拒绝返回 rejected，可在预算内继续；协议/schema 失败终止 failed，权限失败终止 blocked。create_clarification/submit_for_review/finish_run 必须独占一个批次。运行中失败保留先前 receipt，后续不执行。

                       attempt_id:str, cancel_event:threading.Event) -> None

           mission_id:str, run_id:str, cancel_event:threading.Event) -> None

W0 后续在显式动作通过、对象事务创建成功后，由主服务进程接入有界后台 Agent 执行，HTTP 回读快照/SSE，不能同步阻塞事件循环。Agent、Store、工具、事件和领域状态仍归主服务所有；只有单次 Provider I/O 可以进入一个受监督的短生命周期 `spawn` 子进程。该子进程不是服务或队列，不持有 Store、SQLite、领域工具或业务状态。

主进程与每次 Provider 子进程使用不可复用的独占有界通道。子进程只发送 `connected`、`request_started`、`activity`、`content_delta`、`result` 或 `error`，消息必须有当前调用 identity、单调 sequence 和字节上限。主进程拒绝未知、越序、超限或旧调用消息。子进程被终止后，本次通道必须关闭并丢弃，不用于其他调用。

connect deadline 覆盖子进程启动、DNS、TCP 与 TLS；first-event、idle、total 和 Run remaining 覆盖请求发送与响应。取消和服务关闭可以终止子进程，但不能撤回已经发出的字节；请求可能已发送时必须记录 unknown outcome 且不得自动重试。

W2 可用隔离 fake transport 和 fake Store 验证以上接缝，但不添加产品自定义 host、不持有 raw SQLite 或任意文件路径。取消、服务关闭和剩余预算共同约束网络请求；结果未知不重发。

## 9. SSE 公开事件

RunEventEnvelope={event_id:Key,event_type:下列事件,occurred_at:UTC,workspace_id:ID,mission_id:ID,run_id:ID,sequence:正整数,public_payload:对应严格payload}。保留现有 /api/events 的 connected envelope；正式 Run 用独立严格模型，不扩大旧测试接口的含义。

公开事件输入是 event_type 与下表 payload 的判别联合；event_id/sequence/身份/时间由 Store 生成，W2 不自报可信序号。
- run_started：{status:running}。
- message_created：{message_id:ID,role:user|assistant}；不夹带原始输入/隐藏 transcript。
- model_started：{turn_index:正整数}。
- model_delta：{turn_index:正整数,content:string}；每段最多 4096 code points，仅当前连接，不持久化。
- model_completed：{turn_index:正整数,provider_receipt_id:ID}。
- tool_requested / tool_started：{call_id:Key,name:领域工具名,ordinal:正整数}。
- tool_completed：{call_id:Key,tool_receipt_id:ID,status:succeeded|rejected}。
- tool_failed：{call_id:Key,error_code:Key}。
- draft_updated：{draft_id:ID,version:正整数,sha256:Hash}。
- clarification_requested：{clarification_id:ID,draft_version:正整数,draft_sha256:Hash}。
- run_completed / run_partial / run_blocked / run_failed / run_cancelled：{status:Run状态,terminal_receipt_id:ID?,error_code:Key?}；event_type 与状态必须匹配。路径二不能生成 completed 成功。

按 Run 单调递增 sequence；阶段/收据/终态事件持久化，delta 不逐条存库。重连用 event_id+sequence 去重并 GET RunSnapshot，最终公开摘要只从持久的 final_output 恢复；中间丢 delta 时显示快照/不完整提示，不能拼造完整文本或恢复隐藏推理。旧 cursor 无法恢复则明确要求回读快照，不返回假连续事件。

## 10. 持久化与后续集成边界

W0.2 保持 user_version=1 和现有 workspaces 精确 schema 不变；不创建 Source/Mission/Run/receipt 表，不让 doctor 迁移，不触碰用户实际 data_dir。
