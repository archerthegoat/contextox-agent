## 行为与边界

- Run 默认流式。仅 `provider_stream_interrupted` 或已定位 `sse_wire` 超限，可在同一 Run 内自动改为非流式一次。替代请求占下一个请求序号，总计仍不超过 8 次；共用剩余 Run 时间，单请求输出上限仍为已批准的 16384。Provider 内部 `max_retries=0` 不变，由 Agent 统一计数。
- 替代请求沿用原 messages、tools、用户标识及内容预算。每次尝试独立保存 ContextManifest、ProviderReceipt、model_started 事件；后者用 `transport=non_stream`、`fallback_of_turn_index=前一请求序号` 关联。之前完成的领域工具不重放，失败流中未形成完整响应的工具不执行。
- 降级前重新检查源权限、文件完整性及任务/草案/消息上下文；变化时停止。取消、权限/认证错误、协议错误、超时结果未知、请求体/有效正文/单事件/IPC 超限不降级；替代失败或预算耗尽也不追加请求。
- 合法草案或完整模型响应缺 usage 时保留 token 原始 null，派生 `usage_status=missing`，以明确的成功回执标记继续。既有结构、权限、工具批次和终态校验继续生效；缺用量不能使非法候选通过，也不能代表任务完成。
- Workbench 显示已知用量小计、缺用量请求数，不把缺失部分报为已知零。失败流的实时部分输出标为非结果；最终回答只取持久化最终输出。历史回放沿用现有规则，不补造瞬时 delta；降级事件与最终回答可回读。
- 旧的 `provider_usage_unknown`、无回执请求、失败替代仍阻塞后续消息。原失败流只有与相邻成功替代回执及明确关联事件共同核对后才可继续。旧校准记录不改写、不补零。
