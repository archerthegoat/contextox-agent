# 数契产品片 V4 A｜45 秒无旁白脚本

状态：`ready_for_production`。A 版 12 秒方向样片已由用户选中；这份脚本把同一视觉与音乐语言扩展到完整产品流程。成片仍是候选，不替换 README、站点或公开下载。

## 观众要带走的一句话

同一份数据出现多个答案，往往不是不会算，而是哪些算进去、退款怎么处理、按哪个时间还没说清。数契先把这些关键规则问明白，再把人的决定、依据和未知事项留进候选定义。

## 事实与边界

- 华东公开合成订单共四笔：`120 paid`、`50 refunded`、`199 pending`、`320 paid`。
- 所有状态相加为 `689`；只统计 `paid` 为 `440`；已支付再扣除退款为 `390`。
- 三个数字只用于解释规则差异，不冒充产品计算结果。
- Workbench 画面基于当前本地产品和公开合成资料；后续界面特写一一对应现有的发送、澄清、回答确认、候选成果和“查看本轮变化”状态。
- 产品最终停在候选定义；不展示正式发布、生产写入或已经验证的客户价值。
- 没有用户真人录音，因此不使用 TTS、声音克隆或合成旁白。

| 2.5–6.5s | 保留精确规则演示：三套取舍依次覆盖同一张表；每次只显示一个结果 | `全算 689` / `只算已支付 440` / `再扣退款 390` | 三次笔触只覆盖框线绘制 |
| 6.5–7.5s | 三个数停住，硬切成大白话结论 | `不是算错，是规则没说清` | 音乐抽空一拍 |
| 7.5–12.0s | 保留 A 样片 Workbench 入口：依次确认三份已在范围内的资料，光标进入真实输入框，目标文字出现 | `确认资料，说目标` | 界面进入一声纸切；音乐恢复 |
| 12.0–15.5s | 光标沿真实坐标移动到“发送”并按下；镜头以按钮为锚小幅推近，顶部进度从明确目标推进到理解资料 | `发送后，开始理解 3 份资料` | 发送点击与鼓点同帧；不叠夸张 impact |
| 15.5–21.0s | Agent 依次展开三个会改变结果的问题；当前问题放大，其余保持弱化 | `待支付算不算？` / `退款从哪里扣？` / `按哪个时间归属？` | 每个问题在强拍落定；不加卡片弹跳音 |
| 21.0–27.0s | 光标逐项选择大白话回答，最后按下真实的“确认并继续” | `只统计已支付` / `退款从原订单地区扣除` / `按支付时间归属` | 三次轻点击；确认使用一声短、克制的原创提示音 |
| 27.0–33.0s | 候选定义在界面特写中更新；名称、解释、已确认规则、关系和资料来源分层出现 | `回答变成候选定义` | 音乐能量抬升；成果出现使用短展开音 |
| 33.0–37.0s | 光标按下“查看本轮变化”；回答、出处和仍未知事项从候选定义对应位置展开 | `变化、出处、未知，都能回看` | 一声轻点击；三条变化按节拍落定 |
| 37.0–42.0s | 二分画面说明分工：通用执行型 Agent 接收清楚目标并完成代码／SQL／文档；数契在执行前把资料、规则、确认和未知说清 | `先把定义说清，再交给执行` | 音乐降低，让 5 秒文案可读；末拍恢复 |
